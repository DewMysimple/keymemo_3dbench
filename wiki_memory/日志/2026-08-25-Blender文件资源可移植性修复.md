# Blender 文件资源可移植性修复

## 目标

修复从 GitHub 项目打开 `scene_workbench/blender/Verminoble_Scene_Mirror_5_0.blend` 时场景大面积显示洋红色、材质信息丢失的问题，并保证后续重建不会恢复错误资源路径。

## 原因

- Blender 验证报告显示主文件引用了 32 个外部图像/视频和 1 个外部字体。
- 这些路径指向被 `.gitignore` 忽略的 `scene_workbench/source_snapshot/` 与 `scene_workbench/generated/`，普通 GitHub 克隆不包含它们。
- 缺失的图像纹理会在 Blender 中显示为洋红色；这不是几何数据丢失，而是外部资源不可达。

## 修改

- 新增 `scene_workbench/tools/portable_blend_assets.py`，将 source snapshot 资源映射到仓库已跟踪的 `public/.../xp` 资源。
- 新增 `scene_workbench/tools/repair_blend_assets.py`，用于修复已生成的主 `.blend` 文件。
- 更新 Blender 构建脚本，使以后重建自动使用可移植路径，并将生成的 Ground PNG 与转换后的 Canela 字体嵌入主文件。
- 更新 Blender 验证器：允许已嵌入资源，同时拒绝不存在、非相对或不在可发布资源根目录下的外部资源路径。
- 更新工作区 README，记录资源可移植规则与修复命令。
- 重新生成并保存主 `.blend`，同时更新构建和验证报告。

## 验证

- Blender 5.0 完整重建成功。
- `validate_blend.py`：`passed: true`；26 个可编辑水彩层、12 个视频场景、27 个源网格和 3141 个程序草叶保持完整。
- 资源结果：31 个外部资源均指向 `public/.../xp`，1 个 Ground 图集已嵌入，1 个字体已嵌入，未解析资源为 0。
- 默认 `ARTIST_EDIT` 场景以 Blender EEVEE 渲染成功，结果不再出现洋红色缺失纹理。
- `git diff --check` 通过。

## 结果与遗留问题

主 `.blend` 已不再依赖被忽略的 `source_snapshot/` 或 `generated/` 路径。原始媒体的公开授权边界仍按项目现有约束执行；当前仅复用仓库已有的 `public` 资源路径，未新增源素材公开副本。

## 待确认长期记忆

- Blender 主文件的外部资源必须指向仓库跟踪的 `public/.../xp` 路径，或明确嵌入 `.blend`；可由验证器持续检查。
